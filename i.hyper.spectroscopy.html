DESCRIPTION

i.hyper.spectroscopy performs per-pixel spectral feature interpretation of hyperspectral imagery imported as 3D raster maps (raster_3d) by i.hyper.import.

The module reads wavelength metadata from hyperspectral 3D raster bands, computes local band depths across the VNIR-SWIR range (400–2500 nm), matches detected absorption features to a physics-based database of 163 absorbing species entries, and scores 58 composite material hypotheses per pixel. Two output rasters are produced: a dominant-class integer map and a confidence map.

i.hyper.spectroscopy is part of the i.hyper module family.

Interpretation pipeline

The engine works in three layers:

  1. Feature layer — For each band, the local band depth is estimated as max(0, 1 − R_band / R_continuum), where the continuum is the maximum reflectance within a ±150 nm sliding window. Bands with depth below min_band_depth are discarded.
  2. Chromophore layer — Detected features are matched against the built-in absorption feature database. Each match scores the candidate absorbing species by band-depth strength and detection multiplicity.
  3. Evidence layer — Composite signatures (rules requiring specific combinations of species) are evaluated per pixel. Rules that pass all required-species tests receive a score equal to their base score plus a bonus for each optional species also detected.

The class code with the highest score is written to the output map. Pixels where all composite scores fall below 0.10 receive class 0 (unknown).

NOTES

Input requirements

The module expects a 3D raster map created by i.hyper.import or any 3D raster with wavelength metadata in one of the two supported formats:

  • r3.info history — lines formatted as Band N: WAVELENGTH nm, FWHM: F nm (written by i.hyper.import)
  • r.support per-band metadata — fields wavelength=, FWHM=, valid=, unit= in the description of mapname#N rasters

Spectra must be in surface reflectance units (0–1 range). Apply atmospheric correction (e.g., i.hyper.atcorr or i.hyper.smac) before using this module.

Band depth computation

Band depth for band i at wavelength λi is:

depth_i = max(0, 1 - R_i / max(R_j  for all j where |lambda_j - lambda_i| < 150 nm,
                               j != i, and j in the same coverage segment))

The continuum is the brightest neighbouring band within the ±150 nm window that the sensor actually measured next to the feature. Most airborne and drone products drop the two water-vapour windows, and a plain distance window then reaches across the hole and takes the continuum from the far side, which is not a shoulder of the feature at all. On an EMIT cube the gap at 1320-1439 nm is only 119 nm wide, so 10 of 244 bands were affected, and the five bands carrying the 1400-1500 nm water feature read a depth of about 0.62 instead of 0.41.

A gap is detected relative to the sensor's own sampling: a spacing above max(50 nm, 5 × median spacing). That keeps a coarse multispectral sensor, where 60 nm between bands is normal, in a single segment, while still splitting a 5 nm imaging spectrometer at a 150 nm hole.

A band with no neighbour inside its own segment has no continuum and therefore no measurable depth: it reports NaN in full-map mode and 0 in point mode, not the 1 - R that a default continuum of 1.0 used to produce. That default invented a deep absorption at every isolated band, and the deeper the darker the surface.

Typical thresholds:

depthInterpretation
0.00No absorption
0.01-0.03Trace / below detection
0.03-0.10Detectable — default threshold 0.02
0.10-0.30Moderate; most composite rules activate here
> 0.30Strong; nearly pure mineral or dense canopy

Storage scale of the reflectance values

Band depth is a ratio, so the feature detection does not care whether the cube holds 0-1 reflectance or reflectance scaled by 10000, as surface-reflectance products commonly do. The absolute thresholds do care: min_reflectance, max_reflectance and sand_albedo_threshold are all expressed in 0-1 reflectance.

reflectance_scale= is the divisor that converts stored values to reflectance. With the default 0 it is read from the cube's own value range and reported:

Reflectance scale detected: 10000 (stored value / 10000 = reflectance)

Detection picks 1, 100, 1000 or 10000 from the cube's maximum. Give the value explicitly for a cube whose range does not reveal it — a scene that happens to be entirely dark, for instance.

Note for existing command lines: before this, the absolute thresholds were compared against the stored values directly, so working on a cube scaled by 10000 meant passing sand_albedo_threshold=2500 to mean 0.25. That value now means a reflectance of 2500 and will never be reached. Pass 0.25.

Detected, absent, or indeterminate

Band depth is a ratio, so it says nothing about the absolute size of the dip. On a surface reflecting 2 % in the SWIR, a depth of 0.3 is a reflectance difference of 0.006, at or below the noise of an atmospherically corrected imaging spectrometer. Measured on the C2RD Pourrières ground targets, every apparent polyamide detection — N-H 1535 nm and amide 2049 nm depths of 0.12 to 0.31 — came from a surface below 0.07 SWIR reflectance, and the apparent depth tracked darkness rather than material.

A species whose own bands are all darker than min_reflectance is therefore reported as indeterminate: neither detected nor absent. No rule that needs that species, as a required or as a required-absent species, is scored at such a pixel. Treating "unreadable" as "absent" is the same mistake as treating an unsampled exclusion as a pass, and it has the same consequence: the rule fires on exactly the surface that cannot support it. With the default 0.02 this removes the open-water false positives on the C2RD scene; raise it towards 0.07 for work on dark targets.

validity= writes the per-pixel outcome, which the class map alone cannot express:

codemeaning
NULLthe cube has no data here
1classified
2unclassified — readable, but no rule fired
3low signal — every band below min_reflectance
4saturated — a band above max_reflectance

Low-signal and saturated pixels are left unclassified rather than passed off as an ordinary no-match. On the C2RD scene the white glass-fibre panel reads 113 % reflectance at 550 nm with no data through the SWIR, and came out of earlier runs merely "unclassified", indistinguishable from a confident negative.

Sensor band coverage

Before scoring, the module checks which of its composite rules this sensor can actually decide, and reports the rest as warnings:

WARNING: Rule <kaolinite> is disabled for this sensor: required species
         <Al-OH_clay> is outside this sensor's bands.

A rule is disabled when the sensor samples none of the bands of one of its required species, or none of the bands of one of its required-absent species. The second case matters more than it looks: an exclusion that cannot be tested would otherwise pass everywhere, turning a veto into a no-op and letting the rule fire on exactly the material it was written to reject. Such a rule is dropped rather than silently relaxed.

A band window counts as sampled only when a band falls near its nominal centre, not merely somewhere inside the window. Without that test a sensor whose bands stop at 1482 nm would count as covering the 1400-1500 nm water window, and the engine would read a band depth off the edge of a spectral gap. Cubes that drop the water-vapour windows — most airborne and drone products do — are the normal case, not an exception.

Per-band detection thresholds

A species' bands can differ in strength by a factor of two or more, so a single species-level threshold serves none of them well. A database entry may therefore carry its own min_depth, which applies to that entry's bands alone; the effective threshold for a band is the deepest of its own floor, the rule's min_depth_overrides entry and the global min_band_depth. The open-water exclusion uses this: it vetoes on a depth of 0.60 at 970 nm, 0.55 at 1200 nm and 0.50 at 1940 nm, and is deliberately out of reach at 1450 nm, where leaf water alone reaches 0.54 and so cannot separate water from vegetation.

Composite scoring

Each composite rule defines a base_score (0-1) and a list of required species and optional bonus species. A rule is scored at a pixel when every required species is detected, no required_absent species is detected, and every species the rule names is both sampled by this sensor and measurable here. The reported confidence is then:

evidence_sp = sqrt(depth_margin_sp * band_support_sp)
evidence    = geometric mean over required species of evidence_sp
strength    = 0.55 + 0.45 * evidence
score       = min(1.0, base_score * strength * (1.0 + 0.05 * bonus_count))
  • depth_margin_sp is how far the species' deepest band clears its own threshold, scaled over 0.20 of extra depth and clipped to [0, 1]
  • band_support_sp is the fraction of that species' sampled bands which cleared the threshold
  • bonus_count is the number of bonus species also detected

The base_score is therefore a ceiling that says how diagnostic the rule is when it fires, and the pixel's own evidence decides how much of that ceiling it earns. A match that only just clears every threshold keeps 55 % of the base score; one well clear of all of them keeps all of it. Before this, the confidence was base_score × bonus_factor and carried no information about fit at all, which is how a strict run on the C2RD scene could report a mean confidence of 0.99 over what was a degenerate two-way split.

The two components are deliberately independent: a single band scraping over the threshold while its neighbours stay flat is a spike, whereas the same depth across six of eight bands is an absorption band, and the geometric mean requires both. Using the geometric mean across required species means one species sitting at its threshold pulls the whole match down without zeroing it, and adding a required species to a rule can never raise its score.

Confidence is not a correctness probability. It measures how well the pixel fits the rule that was applied, which cannot detect a rule that is not diagnostic in the first place. On the C2RD scene the surviving misclassifications — a red roof, an orange court floor and a windsock all read as phycoerythrin_algae — have genuinely deep features in the windows the rule tests, and score high for that reason. Confidence calibration narrows what a score means; it does not substitute for rule specificity.

Band slice extraction

All Z-slices are extracted via Rast3d_extract_z_slice() from the GRASS raster3d library (libgrass_g3d), which opens the 3D map with RASTER3D_NO_CACHE and calls Rast3d_get_block() in tile-bulk mode. Each tile at the target depth is loaded exactly once from disk, compared to one function call per voxel in the default cache-based API.

Atmospheric contamination flag

If bands matching O2 A/B-band (690, 760 nm) or H2O atmospheric (820, 940, 1140 nm) absorptions are detected above min_band_depth, a warning is issued advising verification of atmospheric correction.

SWIR overlap warning

When features are detected in the 2280–2390 nm zone and multiple competing species (carbonate CO3, CH hydrocarbon, Mg-OH) are matched, a disambiguation warning is issued. Use FWHM as a discriminant: narrow features (< 30 nm) indicate organic CH, broad features (> 80 nm) indicate minerals.

Point mode output

In point mode (-p), the interpretation report is written to the console via gs.message(). The report lists:

  • Dominant class and confidence
  • All detected features above the depth threshold
  • Chromophore assignments ranked by confidence
  • Ranked material hypotheses (top 8 by default, all with -v)
  • Any flag notes (atmospheric and overlap warnings, rules disabled for this sensor, species reported as indeterminate)

Flags

The -n flag restricts processing to only bands marked as valid=1 in metadata. Useful for excluding atmospheric water vapour absorption bands flagged during import.

The -i flag prints the band wavelength table and exits without processing any raster data. Use this first to verify sensor coverage and metadata completeness.

The -p flag activates point mode. A coordinates=east,north value is required. The spectrum at the specified location is extracted and the full interpretation engine runs on that single pixel.

The -v flag prints the full hypothesis ranking in point mode. Without -v, only the top 8 hypotheses are shown.

Output metadata

The class map (output) receives category labels automatically via r.category, one label per class code. Both output maps receive descriptive metadata via r.support. The confidence map receives a plasma colour table via r.colors.

Testing

The pure-Python interpretation engine can be tested without a running GRASS session using the bundled test_suite.py:

python -m pytest test_suite.py -v

The suite provides 41 tests across database integrity, _band_depth(), interpret_spectrum() (edge cases and physics-based synthetic spectra for green vegetation, liquid water, kaolinite, and stressed vegetation), _compute_depths_numpy(), _build_band_species_index(), score_composites_numpy(), and chromophore confidence scaling. No GRASS installation is required — the test file mocks grass.script and loads the module via importlib.

Limitations

  • Classification accuracy depends strongly on spectral coverage. VNIR-only sensors miss clay, carbonate, and hydroxyl features (> 1400 nm).
  • Spectra must be in surface reflectance (0–1). Radiance or DN inputs produce invalid results.
  • The ±150 nm continuum window may blend closely spaced features (e.g., the 2330/2350 nm carbonate doublet).
  • Dense vegetation with strong water absorption may trigger multiple competing hypotheses with similar scores.
  • The chrysotile_asbestos class (27) requires both 2320 nm and 2370 nm Mg-OH features; low SWIR2 SNR may miss it.

EXAMPLES

# Check band wavelengths and metadata before processing
i.hyper.spectroscopy input=enmap_boa -i

# Full-map classification: dominant class + confidence
i.hyper.spectroscopy input=enmap_boa \
                     output=enmap_class \
                     confidence=enmap_conf

# Use only valid bands, lower detection threshold for subtle features
i.hyper.spectroscopy input=enmap_boa \
                     output=enmap_class \
                     confidence=enmap_conf \
                     min_band_depth=0.01 \
                     -n

# Point-mode interpretation at a known mineral outcrop
i.hyper.spectroscopy input=enmap_boa \
                     coordinates=450320,5317880 \
                     -p -v

# Typical full workflow from import to classification
# 1. Import
i.hyper.import input=/data/ENMAP_L2A.hdf product=enmap output=enmap

# 2. Atmospheric correction
i.hyper.smac input=enmap output=enmap_boa

# 3. Continuum removal (optional — sharpens absorption depths)
i.hyper.continuum input=enmap_boa output=enmap_cr

# 4. Classify
i.hyper.spectroscopy input=enmap_cr \
                     output=enmap_class \
                     confidence=enmap_conf \
                     -n

# 5. Visualise
d.rast map=enmap_class
d.legend map=enmap_class
r.univar map=enmap_conf zones=enmap_class

# Extract pixels classified as chrysotile asbestos (class 27)
r.mapcalc expression="asbestos_mask = if(enmap_class == 27, 1, null())"
r.colors map=asbestos_mask color=reds
r.stats -a input=asbestos_mask

# Combine spectroscopy with geology for confirmed argillic alteration
i.hyper.geology input=enmap_cr \
                output_alteration=enmap_alteration

r.mapcalc expression="argillic_confirmed = \
    if(enmap_class == 6 && enmap_alteration == 4, 1, null())"
